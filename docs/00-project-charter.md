# 项目章程

## 使命

在不一次性重写 YL 计算核心的前提下，把“位置敏感、出错即崩溃”的输入系统迁移为：

- 简洁且使用物理概念命名的输入；
- 可在计算前完整检查的强类型问题状态；
- 明确区分输入错误、能力不支持和求解失败；
- 新旧路径可在内存状态、数值结果和物理判据上比较；
- 每一步均可回退到固定的 YL 基线。

## 范围

项目包含：

- YL 输入读取和初始化的加固；
- `ProblemState`、`RuntimeState` 和受控提交接口；
- legacy 与 modern 两种输入适配器；
- 简洁输入格式、单位、引用和跨字段规则；
- 状态摘要、回归算例、故障探针和物理验证；
- 为迁移所必需的求解器模块边界整理。

项目暂不包含：

- 为了代码美观而全面重写单元、材料和求解算法；
- 未经基准支撑的数值算法替换；
- 自动修正含糊或不完整的工程输入；
- 通过生成旧 deck 来实现现代输入；
- 同时维护两个行为不同却都叫 YL 的生产求解器。

## 成功标准

普通二维静力算例最终应能用约 30～50 行输入表达；复杂能力可以更长，但只出现该能力真正
需要的字段。所有现代输入必须在进入组装前得到确定结果：`READY`、`INVALID_INPUT` 或
`UNSUPPORTED_CAPABILITY`，不得以进程崩溃代表输入错误。

生产能力必须同时满足：

1. 输入 schema 通过；
2. 语义和单位规则通过；
3. 初始化状态确定且可摘要；
4. 与基线数值结果在规定容差内一致；
5. 至少一个独立物理判据通过。

## 非功能性约束

- 基线可重复：编译器、依赖、源码提交和算例哈希可追溯。
- 错误可定位：至少包含阶段、对象、字段以及来源位置。
- 初始化可中止：失败时不留下半初始化全局状态。
- 能力显式：所有开放组合由白名单声明。
- 变更可审计：默认值、派生值和单位换算进入构建清单。

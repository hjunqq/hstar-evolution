# 验收、证据与发布

## 一项任务如何完成

开工前按 `templates/task.md` 写清能力组合、依赖、变更边界、预期行为、正负测试和证据位置。
完成后提交代码/文档、运行证据、未覆盖项和风险。评审者检查测试是否覆盖实际消费者，而非
仅验证新 setter 能把自己刚写入的值再读出来。

日常可本地提交；合并、阶段结项和远程发布按项目负责人指定流程执行。不得通过直接修改
reference 或 expected 数值让候选通过。没有独立复核人时可继续开发，但阶段保持 IN_REVIEW。

## 阶段出口

| 阶段 | 必需证据 | 不能据此声称 |
|---|---|---|
| M0 | 来源/哈希、干净构建、隔离运行、两例重复结果、模型及容差说明 | 历史算例物理正确、现代输入可用 |
| M1 | 所选路径读取清单、全部登记负例可控失败、正常例回归 | YL 所有输入已安全 |
| M2 | 多检查点状态及字段映射、确定性、比较器反例、扰动检出 | 所有物理能力已理解 |
| M3 | 类型/所有权、校验/派生来源、事务失败及恢复、bridge 状态等价 | modern 已实现 |
| M4 | 独立进程新旧差分、全部检查点/数值通过、显式回退 | 未覆盖旧方言可读 |
| M5 | 完整 authoring 规范、无旧控制文件执行、状态/数值/物理/负例、用户说明 | 动力或复杂材料自动支持 |
| M6～M9 子切片 | 新组合的完整矩阵、相邻已支持能力回归、所有新风险处置 | 同名分析的任意组合均支持 |

M0 验收不依赖 M2 状态工具；各门按上表开始适用，避免循环依赖。未适用项须写理由，不能空着。

## 证据包契约

每次候选接受使用独立 ID，例如 `M4-static2d-001`，至少包含：

```text
acceptance.md           范围、判决、复核记录
source-manifest.json    提交、补丁/干净状态、二进制与依赖哈希
input-manifest.json     输入文件名、大小、哈希及来源
run-manifest.json       环境、命令、模式、线程、退出和超时
test-results.json      测试 ID、状态、证据路径与哈希
comparison.json        对齐键、容差版本、差异位置和完整性检查
physics-report.md      公式来源、适用假设、误差及预期关系
limitations.md         未覆盖能力、平台及第三方检查盲区
```

这是待实现的输出契约。所有必需条目及所引用的原始结果都必须可取回，报告不能只留下
临时 `/tmp` 路径。小型摘要随仓库管理，大产物可归档到指定存储；验收前核验哈希。
每次发布证据保留到该版本停止支持之后；负责人决定删除时间。不得把执行时间当证据有效期，
证据与精确源码、输入、比较器和环境绑定，任一变化需判定并重跑受影响项。

## 判决规则

ACCEPTED：必需门全部 PASS，证据完整、无未解释差异、范围和复核签名明确。
REJECTED：有必需门 FAIL，或存在静默降级/截断比较/已知物理错误。
BLOCKED：缺环境、真值、容差或不可取得的证据。BLOCKED 不能当“有条件通过”。

复核人可缩小交付范围，但必须先改能力清单并重跑缩小范围的矩阵，不得用备注豁免失败测试。
开发者和复核人可以使用自动工具辅助；自动全绿不等于负责人签收。

## 能力发布与回退

能力项按完整组合登记：维度、单元公式、材料、场、分析、阶段、边界、求解器、重启和平台。
分别记录 reader、状态等价、数值、物理、失败路径证据，不用单个“已支持”掩盖缺项。

发布步骤：冻结候选提交 → 干净构建 → 执行必需矩阵 → 复核证据 → 负责人接受 → 发布版本及
能力清单。development tag 可用于协作，但不得命名为生产版本。未获得接受不自动打发布标签。

回退使用上一已接受构建和独立运行目录，用户显式选择；不在 modern 解析失败时自动改用旧输入。
禁止覆盖原输入、golden 或旧结果。重启文件必须带版本/布局身份，未证明兼容就拒绝跨版本续算。
新发现缺陷时暂停相关组合，复现、补负例、修复并重过门；其余组合按依赖影响决定是否暂停。

## 基线变更

修改参考值必须另建任务，给出旧错误证据、独立判据、新旧结果、影响范围与复核结论。
同时保存旧基线身份、新基线身份及迁移说明。单纯提高容差、换求解器或修改网格不属于
“格式迁移等价”，必须作为明确的计算配置或算法变更验收。

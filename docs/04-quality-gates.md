# 质量门与停止规则

测试 ID、容差和反例按 [测试规格](06-test-specification.md) 实施，适用阶段及判决以
[验收流程](07-acceptance-and-release.md) 为准。工具未实现或环境缺失必须标 NOT_RUN/BLOCKED。
下列要求针对受影响的已开放能力；M0 不以尚未开发的 M2 状态工具作为前置条件。

## 每次提交

- Fortran 编译无新增 warning；
- 输入和状态单元测试通过；
- 不改变未涉及能力的 state fingerprint；
- 新错误路径有负向测试；
- 不新增从 modern 路径读取 legacy deck 的行为。

## 每个迁移子阶段

| 质量门 | 判据 |
|---|---|
| Build | 支持平台的 Debug/Release 及编译器可用的运行时检查通过；不可用检测及第三方盲区单列 |
| Input | schema、单位、引用、范围和组合检查通过 |
| State | 新旧入口状态相同，或差异被逐字段批准 |
| Numerical | 位移、反力、应力、特征值等在各自容差内 |
| Physics | 解析解、patch test、守恒或消融关系通过 |
| Failure | 所有登记坏输入可控退出且消息可定位 |
| Capability | 白名单和证据等级更新 |
| Documentation | 用户输入、限制和迁移说明完整 |

## 必须停止扩展的情况

出现以下情况时，当前能力不得继续增加字段或算例，必须先修基础层：

- 相同输入产生非决定性 state fingerprint；
- 输入错误仍能导致崩溃或半初始化；
- 新旧结果不同但无法定位到入口状态或明确算法修改；
- 为了跑通而添加无法解释的默认值；
- 一个字段在两个路径拥有不同语义；
- 自动回退掩盖 modern 解析或验证失败；
- 只有历史结果、没有物理判据，却准备标记 production。

## 差异处置

所有差异只能归入三类：

- `REGRESSION`：应保持但发生变化，必须修复；
- `INTENTIONAL_FIX`：确认旧行为错误，保留旧基线并新增修复后的物理证据；
- `EXPECTED_REFORMULATION`：算法或离散方式明确变化，需要独立基准和版本说明。

禁止以“新结果看起来合理”关闭差异。

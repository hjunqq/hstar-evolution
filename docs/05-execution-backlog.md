# 执行与任务拆分

## 使用方式与范围

本文件将 M0～M5 拆成可交给开发者的任务；M6～M9 只按需求准备下一条能力切片。
一次只推进一条主切片，最多同时处理一个与之相关的缺陷。每项任务建议控制在一次可评审变更内；
若同时修改 reader、材料算法、网格或线性求解器，应继续拆分。

任务状态：`TODO → IN_PROGRESS → IN_REVIEW → ACCEPTED`，无法继续时标为 `BLOCKED` 并记录
具体缺失证据。代码合并不自动等于阶段验收。模板见 `templates/task.md`。

## 开工前必须明确的基线

当前导入的是历史提交 `5414e737484edf2f53efbfd2bafd3702ebbbb88a`，并未证明它能运行从当前
cases 工作区导入的算例。原仓库还有未提交修复，不能认定这个快照代表今天的生产版本。

M0 应保留三个明确身份：历史导入快照、经审查的可构建参考版本、当前迁移候选。
若必须引入现有 YL 修复，应列出差异及每项修复的理由、回归证据，再以独立提交导入；
不得整体覆盖快照或因“新版本能跑”就替换基准。

两套种子算例的 `.glb` 都声明 `PROFILE`。先复现这个配置，再为 PARDISO 单独建立变体。
算例名称不能证明物理模型：Cook 和 Lamé 都必须核实网格、平面假设、材料、载荷、约束和单位。

## 后续切片的统一开工条件

每次只选 M6～M9 中一个明确组合，例如“B8 + 线弹性 + 单阶段静力”，先提交一页设计：

1. 支持组合、明确排除项和用户真实需求。
2. 一个最小正例、一个已有回归例、一个独立物理判据、至少三个负例。
3. 所有新增输入及阶段内消费者、检查点和状态所有权。
4. 与上一能力的交叉影响：材料、单元、场、阶段、求解器、重启。
5. 前置任务、预计工作量区间、最大调查时间和停止条件。

每完成两个任务回顾一次实际成本，再估计下两个任务。总体工期在 M0/M2 前不作承诺。
若一个未知问题连续占用两次工作会话，应写出最小复现和证据缺口，决定解决、缩小切片或暂缓；
不可用填默认值方式解除阻塞。

## 第一轮可以直接开展的工作

先做 M0-01～M0-03，暂不更改算法与现代输入语法。首轮评审交付：来源清单、构建日志、
运行器隔离与超时试验。其后才运行并冻结两例结果，无法复现时先判定源码/输入版本配对问题。

# ADR-0008：三项常设裁定——功能域顺序、输入分层、长尾处置

- 状态：接受（负责人 Huijun，2026-09-10）
- 相关：ADR-0007（静力是第一个切片）、ADR-0003（CAE 对象模型与 SI）、
  `docs/02-migration-plan.md` M5～M9、R28（跨路径容差）

## 背景

2026-09-10 的六问汇报提出三个架构级待裁定项。负责人一并裁定，**并明确要求
后续同类执行排序不再逐条确认**——即这三条是**常设裁定**，不是一次性答复。

## 决策

### 1. 功能域顺序：静力五件套完成后直接进入材料域

材料域（`.mat` 104 处 + 液化 4 处，里程碑 M6.4/M6.5）是第二个功能域。

**这是执行排序，不再作为人工决策项。** 后续同类的「先做哪个域 / 先做哪个子阶段」
按计划顺序与依赖关系自行决定，不再逐条请示。

选择理由（记录以备复查）：材料域的输入结构与已建成的 `props` / `materials[]` **同形**，
是检验「新输入体系统一性」最小代价的试金石；施工过程域记录数最多且涉及跨阶段状态传递，
若先做会把统一性问题与状态传递问题纠缠在一起。

### 2. 新输入分层：`authoring schema → ProblemState → solver`，单轨

**统一路径，不设旁路。** 判定标准：

> **一个功能域，只有在进入 authoring schema 并完成到 `ProblemState` 的映射之后，
> 才算进入新输入体系。**

**明确禁止长期双轨**——即「`ProblemState` 已扩展、authoring schema 滞后」的状态。
理由是这正是各功能域逐渐形成孤立格式的机制：`ProblemState` 先行时，每个域会按自己
最方便的形状扩类型，authoring 层事后再去追，追不动就各写各的。

**允许的短期例外**：单个任务内部为了先跑通 legacy 适配而临时扩 `ProblemState`，
但**该任务的出口条件必须包含 authoring schema 的对应扩展**，不得跨任务遗留。
静力域当前正处于这种状态（`ProblemState` 已完整、`schemas/case.schema.json`
仍是 bootstrap），**M5 就是补齐这一段的任务**。

### 3. 长尾能力：现在不逐项认定，只保证 legacy 路径不被破坏

- **现在不逐项认定** 反分析、可靠度、水平集、网格细化、优化等长尾能力的去留。
- **不提前为全部长尾能力设计新 schema 兼容位。** 为可能永不迁移的能力预留结构，
  成本落在每一个真实功能域身上。
- **现阶段唯一要求**：未进入明确迁移范围的能力，**legacy 路径不被破坏**。
- **到相应阶段再依据三条决定** migrate / legacy-only / retire：
  **真实旧算例 + 当前实际需求 + 可验证判据**。三者缺一不足以判 migrate。

### 4. M4-02 的数值容差：先测噪声，不做成研究项目

**明确不把容差定案做成一个新的研究项目。** 顺序固定为：

1. **先测**：同一二进制、同一输入、同一环境，重复运行，**是否存在实际非零噪声**。
2. **只有观察到噪声之后**，才据实测确定容差。
3. **若结果稳定（噪声为零）**，**直接使用严格或近严格比较**，不引入容差参数。

这条同时是 R28 中「判据 13 跨路径容差」的处置方式：容差不是先验设定的数，
是被测出来的数；测不出噪声就不要造一个容差出来。

## 影响

- `docs/02-migration-plan.md` 与 `docs/05-execution-backlog.md` 的域顺序按本裁定执行，
  不再逐条请示。
- M5 的出口条件明确包含「静力域的 authoring schema v1」——否则静力域五件套不闭合。
- 每个新功能域任务的出口条件模板增加一条：**authoring schema 已同步扩展**。
- R28 的关闭路径按第 4 条改写。
- **汇报口径**：下一次面向负责人的汇报只在**静力域完整闭环**或**出现真正影响总体架构的
  冲突**时发生；中间技术过程不汇报。

# ADR-0005：M2 与 M3 在 M4-01 结束后一并签收

- 状态：接受（负责人 Huijun，2026-09-09）
- 相关：ADR-0004（M3 延后出口）、R28（M0 签收后的残留断言）

## 背景

到 2026-09-09，实施进度与验收进度严重脱节：M2-02/M2-03/M3-01/M3-02/M3-03 都是 DONE，
M2-01 是 IN_REVIEW，但**没有任何一个 M2/M3 任务被签收**，Accepted Progress 停在 3/17（仅 M0）。

同时 ADR-0004 把 M3 的「bridge 状态等价」举证责任移交给了 M4-01。该债已于 2026-09-09
由 L3-b 结清（`MATCH=64 MISMATCH=0`，见 `docs/m4/L3b-bridge-report.md`）。

## 决策

**M2 与 M3 在 M4-01 结束后一并签收**，不各自单独签，也不提前签。

理由：
1. M3 的出口条件之一在 ADR-0004 之后本就绑定在 M4-01 上；分开签会让 M3 的签收再次
   出现「条件签收」，而那正是 M1-01/M1-02 拖了一天的形态。
2. M4-01 的影子差分（M4-01 自己的判据）会同时给 M2 的比较器栈提供一次真实使用证据。
   在它跑通之前签 M2，等于签一个尚未被下游用过的工具。
3. 一次签两个阶段的边际成本低于两次分开签：证据链高度重叠（映射表、序列化器、
   比较器、build_runtime、commit）。

## 后果

- **要先建两份验收矩阵。** M2 和 M3 目前**都没有**验收矩阵（M0 有，18 条准则）。
  签收不是「说一句同意」，而是逐条把阶段出口条件映到证据，并标出哪些仍属断言。
  这项工作**不依赖 M4-01**，可以立即并行开始——只有「bridge 状态等价」与影子差分两条要等。
- **判据 18 的那一半仍然缺席。** 与 M0 相同：单人项目没有独立于实现人的复核人。
  签收 M2/M3 时必须同样如实记录，不得因为 M0 已这样签过就淡化。
- **不得因为「都是 DONE」就推定可签。** M0 的经验：18 条里 3 条只是断言而非独立证据，
  而那是逐条核对才发现的。

## 已查明、不构成阻塞的一项

`state-field-map.toml` 的第四个检查点 `restart_ready` **零字段**，STATUS 记为「未覆盖」。
这**不是缺口**：map 自己写明 `covered = false` 并给出理由（restart=0，`resta_read_write(1)`
与 `.rtt/.stf` 单元不在 static_2d 路径上），**而且能力表有 `F1/restart` 方言规则会拒绝
任何 restart≠0 的 deck**。范围边界由门禁强制执行，是可签的形态，签收时按此记录。
